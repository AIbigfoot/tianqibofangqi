# 前端「主机模式（Console / Steam 大画面风格）」实现计划

## 一、Context（为什么做这件事）

用户诉求（原话）：「我希望主界面可以有steam主机模式那样」，并提供了两张 Steam 大画面模式截图作为参考：

- **图A（大画面首页）**：左上「最近游戏」；大型 Hero 区（宽幅图 + 左下大标题 + 一行元信息）；右侧一行大幅封面卡（被聚焦者淡蓝描边、抬升放大）；下方一行标签胶囊；再下方宽幅卡行；深色 + 模糊环境背景；右上角搜索/设置/铃铛/时钟/头像。
- **图B（资源库网格）**：顶部居中搜索框；一行筛选胶囊（所有游戏 96 / 已安装 0 / 合集 3 …）；大幅海报网格、间距大；聚焦卡有蓝色发光描边；底部左侧「STEAM 菜单」徽章、右侧「返回 + B 键」提示。

目标：把这种「大屏、可键盘导航、聚焦高亮、分类标签行、最近观看 Hero + 卡片行、底部提示条」的 TV/主机体验引入本项目主界面。

**关键约束**（来自项目既有规范与文档）：
- 四层架构：L0 `src-tauri`（组合根 + 命令 + 静态前端 ui）/ L1 `crates/app` / L2 `crates/domain`（零 IO）/ L3 `crates/adapters` / L4 `crates/infra`。硬约束：新增功能＝新增实现 + 组合根注册，**不改 L2 领域层核心代码**。
- 技术架构文档 C6 明文要求「新功能以默认关闭的功能开关发布」——因此主机模式必须可关闭、可回退。
- 前端是**自包含静态页，无构建步骤、离线可用**（`ui/index.html` + `ui/styles.css` + `ui/app.js`）。前端资源在构建期被嵌进 exe，改前端后**必须重新构建 exe**。
- 播放画面由**后端原生 mpv 子窗口**按物理像素覆盖网页矩形；原生窗口恒在网页之上，`z-index` 对它无效。
- 标签维度与取值全部来自后端配置，**前端不硬编码维度规则**。
- §1–§10 既有章节与版本号未经用户确认不得修改；附录 A 可续写。注释 / 文案 / 文档一律中文。

## 二、范围决策（含推荐，供拍板）

| # | 决策点 | 推荐 | 理由 |
|---|---|---|---|
| 1 | 形态 | **可切换的模式开关**（默认关闭、F10 或顶栏按钮切换、localStorage 记忆），不替换主界面 | 符合 C6「默认关闭的功能开关」；经典界面承载入库/维度面板/多屏/字幕/迁移等大量交互，替换式回归面积是模式的 4–6 倍；可一键回退、可分阶段验收 |
| 2 | OS 真全屏 | **不做**（主机层用「铺满视口 + 深色环境背景」达成观感） | 避免新增 `core:window:allow-set-fullscreen` 权限与全屏下原生窗口重摆风险 |
| 3 | 手柄 | **本期只做键盘**；手柄作为可选增强单独提交（`gamepadconnected` 后才启用） | Gamepad API 在 WebView2 可用，但存在焦点依赖（mpv 原生窗口抢焦点）、需用户手势才派发、非 Xbox 映射差异、且**沙箱无法自动验证**；键盘零依赖、可目视验证 |
| 4 | 多屏入口 | **主机模式内不提供**，且 `inMulti` 时禁止进入主机模式 | 多屏需每格上报矩形并隐藏故障格窗口，与覆盖式主机层叠加会形成「原生窗口压层 + 底部区域争抢」的第三态，收益低于风险 |
| 5 | 是否新增后端命令 | **不新增**（`invoke_handler` 一行不动） | 见下节「数据来源验证」 |
| 6 | 文档 | **不改 PRD 正文/版本号**；仅在技术架构**附录 A 续写**一节主机模式实施记录 | 按约定，新增 FR 需用户确认 |

**数据来源验证（已核实，无需后端改动）**：
- Hero「最近观看」：`search_items({text:'', filters:{}, sort:'last_watched'})` 的**返回顺序第一项**即「最近观看过的最新一条」（排序在 L2 完成，L1 已读 `playback_state.updated_at` 生成 `SortKey.last_watched_at`，见 [search_service.rs](file:///d:/AI开发项目/视频播放器项目/crates/app/src/search_service.rs#L126-L138)）。**不需要**给 `ItemView` 加 `last_watched_at`——元信息文案用既有 `positionMs / resumePercent / durationMs` 表达。
- 「未看 / 在看 / 已看」胶囊：**本就是后端派生维度** `watch`（`DIM_WATCH = "watch"`，取值常量 未看/在看/已看，规则 `watch_state` 达 95% → 已看，见 [tagging.rs](file:///d:/AI开发项目/视频播放器项目/crates/domain/src/tagging.rs#L61-L64)），启动时由 `builtin_defaults()` 幂等播种。胶囊文案与计数**直接取 `list_dimension_tags('watch')`**，点击即 `toggleTag('watch', name)`，走现有「同维度 OR、跨维度 AND」语义——**维度规则一行都不落进前端**。
- 「所有影片」＝清空筛选（动作，非规则）；「文件缺失」＝对已取回结果做 `filter(i => i.missing)` 纯呈现（`ItemView.missing` 由 L4 判定）。**注意语义**：该计数是「当前结果内的缺失数」，非全库缺失数（不加新命令无法两全），需在文档写明。
- 时钟＝前端 `new Date()`。库统计＝既有 `library_stats`。

## 四、键盘焦点模型

- 维护 `consoleRows: [{ kind:'hero'|'cover'|'chips'|'wide'|'grid', nodes:[HTMLElement] }]`，每次渲染重建。
- 索引状态 `consoleFocus = { screen:'home'|'lib', row, col, desiredCol }`；`desiredCol` 解决「长行 → 短行」上下移动的列记忆（Steam 行为）。
- 统一出口 `applyConsoleFocus()`：清旧 `.focused` → 加新 `.focused` → **手动居中滚动**（禁用 `scrollIntoView`，否则会连带滚动祖先导致整屏跳动）：
  - 横向：`rowEl.scrollLeft += nodeRect.left - rowElRect.left - (rowEl.clientWidth - nodeRect.width)/2`
  - 纵向：仅在节点越出容器上下沿时滚最小距离。
- **每次 `refresh()` 重建 DOM 后必须重挂焦点**：`renderConsoleHome()/renderConsoleLibrary()` 末尾统一调 `applyConsoleFocus()`，并按新行长度 clamp `row/col`（否则会出现焦点落在不存在节点上导致方向键无响应的死态）。

按键语义：

| 键 | 首页屏 | 资源库屏 | 播放中（主机层隐藏） |
|---|---|---|---|
| ←/→ | 行内移动（首尾夹紧，不环绕） | 网格列移动 | 交还原有控件，不拦截 |
| ↑/↓ | 跨行移动（`desiredCol` 记忆） | 网格跨行 | 同上 |
| Enter / Space | `onCardClick(item)`（与鼠标点击同一条路径） | 同 | 同上 |
| Esc | 退出主机模式 | 返回首页 | 若可达则 `closePlayer()` |
| F10 | 全局切换主机模式 | 同 | 同 |

- Space 与方向键需 `preventDefault()`。全局 `keydown` 用 `{capture:true}` 注册一次，**非主机模式立即 return**（保证对经典界面零影响，含现有三处输入框 Enter）。
- `isTypingTarget()`（activeElement 为 INPUT/SELECT/TEXTAREA 或 contenteditable）时不消费导航键；库屏搜索框内 Enter 应用搜索、Esc 清空并 blur、再按 Esc 返回首页。
- `modalOpen()`（存在 `.modal:not(.hidden)`，或 `#subtitle-menu` 非 hidden）时主机导航整体挂起，Esc 交给弹层。

焦点态样式（发光描边 + 抬升放大）：`.card.focused { border-color + box-shadow 蓝色发光; transform: translateY(-6px) scale(1.06); z-index:3; }` + `::after` 角标；`.chip.focused` / `.hero.focused` 同理。与既有 `.flag`(左上)/`.dur`(右上)/`.progress`(底部) 不冲突。

## 五、与现有状态/机制的关系

- **播放态**：`playingId` 存在 → 主机层隐藏，露出既有 `#player-bar`；`closePlayer()` 后主机层自动回归。这与「进游戏就全屏画面」一致，且天然规避原生窗口遮挡。
- **原生窗口**：绝不出现「主机层压在画面上」的设计；规则是「任何原生画面存在时主机层必须隐藏」。
- **多屏**：`inMulti` 时禁止进入；主机模式不提供多屏入口；`enterMulti()/toggleSelectMode()` 加 `consoleOn` 守卫。
- **悬停预览**：主机模式不做悬停预览（`scheduleHover()` 加 `if (consoleOn) return;`）；`preview-click / player-click / multi-click` 监听不动。
- **`dimsOpen`**：进入时强制关闭并记原值，退出还原（避免 `applyView()` 把维度面板重新显示到主机层下）。
- **`selectMode`**：进入时强制 `exitSelectMode()`（否则 `.pick` 与 `body.selecting` 会在主机卡片泄露多选视觉）。
- **`applyView()` 是唯一总开关**：新增主机分支——`consoleOn && !stageOn && !playingId` 时隐藏 `topbar/searchbar/filter-bar/dims/wall/sources`、显示 `#console`；否则走现有逻辑。不另建第二套可见性逻辑。
- **主机模式不做**：添加目录/扫描/数据迁移（需文本输入框，与经典 `#dir-input` 逻辑重复）。顶栏「设置」浮层只放只读/布尔项（悬停预览开关回显、海报尺寸、库统计）+「经典界面」按钮。

## 九、风险与边界

1. **原生窗口遮挡**：mpv 恒在网页之上，`z-index` 无效 → 任何原生画面存在时主机层必须隐藏。
2. **播放期键盘可达性**：原生窗口获得焦点后键盘事件可能不到 WebView（Esc 在播放期不可靠）。以底部控制条「返回」按钮为唯一权威退出路径（本就存在可点）；此风险对经典界面同样存在，非新引入。
3. **滚动/焦点越界**：禁 `scrollIntoView`；行首尾夹紧不环绕；渲染末尾 clamp `row/col`。
4. **两种空态必须分开**：空库 → 「还没有内容」+ 引导切到经典界面入库；筛选无结果 → 列出生效标签 + 「清空筛选」（沿用「不自动放宽条件」语义）。
5. **一次额外全库查询开销**：首页每次刷新多一次 `search_items`（全库 + last_watched 排序）。可选优化：仅当 `searchText==='' && 无筛选 && sortTag==='last_watched'` 时复用 `items[]`；**建议先实现、实测再决定**。
6. **手柄**：焦点依赖、需用户手势、非 Xbox 映射差异、无法自动验证；`gamepadconnected` 后才显示徽章，映射到与键盘同一个命令分发函数（不新增 UI 状态）。
7. **真全屏**：不做；若坚持则须在 `capabilities/default.json` 加 `core:window:allow-set-fullscreen` 并回归全屏下画面贴合与 resize 重摆。
8. **文档边界**：不改 PRD 正文与 §1–§10、版本号；仅在附录 A 续写。
