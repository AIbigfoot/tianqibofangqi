Product Requirements Document

影院（Cinema）— 本地与在线视频统一观看、标签检索、实时字幕与多屏播放

单一应用内完成「找片 → 浏览 → 播放 → 看懂」的完整闭环，覆盖本地文件与在线地址两类片源。 本文档定义产品行为与业务决策，不含技术实现方案。

版本 v1.1 状态 待评审 范围 新产品的首个完整旅程 结构 按模块的功能需求 标记 [TBD] 待定 · [假设] 推断

01背景与目标

用户手上的视频分散在两类地方：本机硬盘上按文件夹堆放的文件，以及需要网络访问的在线地址。 这两类内容目前各自独立：本地文件靠文件管理器翻找，只能看文件名，无法按内容检索；在线地址靠浏览器书签或播放器历史记录， 无法标记与分类。结果是同一个「今晚看什么」的动作被拆到两三个工具里，且每次都要重新定位文件位置。

第二类问题出现在内容本身：外文影片如果没有内嵌或外挂字幕，用户就完全看不懂；而临时去找字幕文件经常对不上版本或时间轴。 第三类是观看形态，用户存在同时看多路视频的需求（对比观看、家庭分屏、多个直播/录像同时跑）， 但现有播放器一次只能承载一路画面。

产品响应与可观察结果

片源分散在硬盘与网络→ 统一媒体源 + 一次入库→ 影片条目与海报墙→ 标签筛选 + 搜索→ 点击海报直接播放→ 无字幕外文视频开启实时字幕→ 可同时播放多路
可观察结果 1用户不需要打开文件管理器或浏览器，在应用内即可定位到任意一部影片并播放。
可观察结果 2用户通过点击标签（含多标签组合）能把影片数量从全库收敛到可一眼浏览的范围。
可观察结果 3对没有字幕的外文视频，用户开启实时字幕后可立即看到随语音同步出现的目标语言字幕，无需先去外部寻找字幕文件。
可观察结果 4用户可在同一屏同时播放 2 路以上视频，并能指定哪一路出声，互不干扰。

说明：本文档不设定量化指标，因为尚未有可支撑的基线数据。

02范围与 P0 旅程

产品形态判定

产品判断 [假设, TBD] 影院定位为桌面客户端（首发以 Windows 为优先平台 [TBD]）。 依据：需求 1 要求直接使用本机文件与在线地址，需要访问本地目录与文件系统；需求 2 的实时字幕在播放过程中持续产生识别负载， 放在本机的算力与隐私成本最低。电视大屏、移动端与投屏作为后续形态预留 [TBD]，不进入 P0。 该判定直接影响全部界面与交互设计，需在评审时优先确认。

入口条件

  • 用户已安装影院客户端，机器上存在至少一个包含视频文件的本地目录，或至少一个可访问的在线视频地址。

P0 最小完整旅程

首次启动→ 添加媒体源→ 扫描入库→ 自动抓取元数据与海报→ 海报墙浏览（悬停自动预览精华片段）→ 按标签筛选 / 搜索→ 点击海报播放→ 无字幕外文视频开启实时字幕→ 多屏模式同时推入第 2 路→ 退出播放，进度已记忆
层级能力在旅程中的作用
P0媒体源添加与扫描入库（FR-01）旅程起点，没有入库就没有一切
P0影片条目、元数据与海报墙（FR-02）承载浏览，以及需求 3 的「悬停自动播放精华片段」
P0标签体系与组合检索（FR-03）解决需求 1 的「通过标签找到电影」
P0播放器与进度记忆（FR-04）完成观看动作
P0实时字幕（FR-05）解决需求 2 的「无字幕外文视频」
P0多视频同时播放（FR-06）解决需求 4 的多路观看
P0可迭代性要求（FR-07）解决需求 5，约束上述模块的扩展方式
不在 P0账号体系、多设备共享同一片库、付费分发、直播电视、商业 DRM 内容、社交分享与单机观看闭环无关，纳入会让首个旅程无法收敛

失败恢复路径（P0 必须覆盖）

失败恢复方式用户可见结果
元数据/海报抓取失败条目进入「元数据待补全」，提供手动匹配与手动上传海报海报墙显示占位海报（文件名 + 渐变底色），条目仍可正常播放
实时字幕引擎不可用降级为：加载外挂字幕文件 / 仅显示原文识别 / 关闭实时字幕明确提示原因，播放不中断
多屏播放超出设备能力拒绝新增路数并提示可调上限，保留已播放路数提示「已到同时播放上限」，其他窗口不受影响
悬停预览不可用（多屏额度不足 / 无精华片段 / 已关闭）只显示信息层，在浮层标注不可用原因；不重试、不抢占正在播放的窗口浏览与筛选不受影响，用户可见明确的降级说明
源文件被移动或删除条目标记「文件缺失」，提供「定位文件」与「忽略」条目在库中保留但置灰，不进入播放

角色权限范围P0 / P1

04功能需求

FR-01媒体源与入库

目的：让本地文件与在线地址进入同一个可检索的库，并为后续所有模块提供统一的条目数据。

布局与入口

主界面左侧为导航区，其中「媒体源」页列出全部已添加的源，并常驻「添加媒体源」入口。首次启动且库为空时，主区域直接展示添加引导，而不是空白海报墙。

处理规则

  • 源类型：本地文件夹、网络位置（局域网共享路径）、在线地址（单个视频直链）。P1 再扩展网盘与订阅型在线源。[TBD] 在线资源的具体边界见开放问题 Q2。
  • 扫描：添加后立即执行一次全量扫描；之后按可配置的触发方式重扫（手动触发为 P0，定时触发为 P1）。
  • 识别：从文件名与所在文件夹路径解析标题与年份，作为元数据抓取的输入；解析失败时不阻塞入库，条目进入「元数据待补全」。
  • 去重：同一物理文件被重复扫描时合并为一条条目，不产生重复海报；同一影片的不同清晰度版本视为不同条目，但互相标记为「另一版本」（便于用户从 A 版本跳转到 B 版本）。
  • 移除源：移除源时保留该源下条目的用户数据（标签、收藏、观看进度），条目状态转为「文件缺失」；用户可选择「同时删除条目与数据」。该选择为不可逆动作，需二次确认。
  • 增量：重扫只处理新增、变更与消失的文件，已识别的元数据与用户标签不被覆盖。

结果与状态变化

扫描完成后，主界面显示新增条目数量；扫描过程中显示进度（已处理 / 总数）并允许取消，取消后已入库的条目保留有效。

字段

字段类型/取值必填可编辑校验
源名称文本是是非空；同名时自动追加序号
源类型本地文件夹 / 网络位置 / 在线地址是否（需重建）—
路径或地址路径字符串 / URL是是（触发重扫）本地路径必须存在且可读；地址必须可解析
扫描排除项目录名或通配模式列表否是支持如 sample、trailer 等常见噪音目录
自动抓取元数据开 / 关是是默认开

异常与边界

场景系统行为
路径不可访问（盘符离线、权限不足）源状态置为「扫描失败」，保留既有条目并提示原因；恢复后重扫仅补增量
在线地址失效（404 / 超时）条目标记「地址失效」，海报墙置灰，不进入播放；提供编辑地址入口
目录中无可识别视频文件提示「未发现可识别的视频文件」，源保留但条目数为 0
扫描中途被取消已入库条目保留，未处理文件在下次扫描时继续

05影片库与海报墙 FR-02

目的：以海报为主要视觉语言呈现影片库，让用户「先看脸再决定看什么」；并实现需求 3 已确认的交互：鼠标移动到海报上自动静音播放该影片的精华片段。

需求第 3 条已确认（v1.1） 用户明确：鼠标移动到海报上即自动播放该影片的精华片段。因此悬停的主行为是「静音自动预览」，标题/评分/标签等信息层与「播放」「详情」按钮是叠加在预览之上的附属信息，不是悬停的主行为。 原始描述「电影有海报，希望通过海报呈现，并且移动到」的中断部分按此落定；原 v1.0 中把预览列为 P1 的判断已作废，预览升级为 P0。 拖拽调整海报墙顺序 / 拖入收藏夹仍为 P1。
FR-02 · FR-03 海报墙 + 标签筛选 + 悬停自动播放精华片段 悬停 300ms 触发 · 演示按 4 倍速推进
用于演示「过载降级」回退态
当前筛选：全部影片（8 部）· 悬停任意海报可预览精华片段

布局

  • 主区域为自适应网格海报墙；网格列数随窗口宽度变化，用户可切换海报尺寸（大 / 中 / 小）。
  • 顶部为检索区：搜索框 + 已选标签条（显示当前生效的标签，可单个移除或一键清空）。
  • 右侧或顶部可切换排序：最近添加、标题、年份、评分、时长、最近观看。
  • 未识别出海报的条目使用占位海报：渐变底色 + 文件名首行文字 + 状态说明，不隐藏该条目。

处理规则

  • 海报来源：优先使用用户手动设置的本地海报图；其次使用元数据源返回的海报。质量不足（分辨过低）时标记「海报待优化」并优先匹配更高质量图。
  • 悬停出发（核心行为）：鼠标移动到海报上停留 300ms 后，海报内开始静音自动播放该影片的精华片段；同时在预览之上叠加信息层：标题、年份与时长、评分、标签（最多展示 4 个）、简介前两行，以及「播放」「详情」两个动作。
  • 移开：鼠标移开或焦点离开后立即停止预览并复位到静止海报帧；不改变当前筛选状态，不跳转页面。
  • 点击海报：默认单击进入详情页，详情页以「播放」为主按钮；悬停浮层的「播放」可直接开始播放。单击行为可在设置中切换为「单击即播放」。
  • 与主播放并行：预览在静音下进行且不改变任何正在播放内容的音频焦点，因此不会打断单路播放，也不会抢走多屏模式下的发声窗口。
  • 详情页：展示完整海报、简介、标签、可用版本、字幕轨道清单、播放进度，并提供编辑标题/年份/海报、添加标签、加入收藏夹。
  • 排序与分页：大库（条目数超过一屏）采用滚动加载，滚动到底部继续加载，不出现空页。

精华片段预览规则（悬停自动播放）

项目规则
触发悬停停留 300ms 后开始播放；设置中关闭「悬停自动预览」时不播放，只显示信息层
片段来源与长度取自影片本体，默认抽取连续 30 秒 作为精华片段；起始位置如何判定为「精华」[TBD]（不在本文档编造具体算法，需先定基线）
音频强制静音：不发声、不改变正在播放内容的音频焦点（含多屏的发声窗口）
播放实例独立播放实例，低优先级；与多屏播放共享同一份解码路数上限
进度副作用不写入观看进度、不改变「在看 / 已看」状态；移开时未播完的预览直接丢弃
并发同一时刻只允许 1 路预览；鼠标移到另一张海报时立即终止上一路并从头开始新的
重复悬停同一海报再次悬停仍从头播放，不记忆上次位置（避免每次停在同一画面）
结束片段播完停在末帧并显示「预览结束」；鼠标移开后复位到静止海报帧
无可用片段显示「无预览片段」，只保留信息层；不重试、不阻塞浏览
过载降级多屏播放已达同时播放上限时，预览被拒绝并在信息层标注原因（可见的降级，不静默失败、不抢占正在播放的窗口）
可关闭设置中可整体关闭悬停预览，兼顾省电与无障碍需求

结果与状态变化

悬停与点击均为浏览行为，不产生持久化状态；编辑标题/海报/标签为持久化动作，写入条目并影响筛选结果。编辑后海报墙立即重排或重绘。

06标签与检索 FR-03

目的：满足需求 1「视频有各种标签，用户可以通过标签找到自己的电影」。

标签体系

维度取值来源取值示例来源优先级
内容类型元数据源 / 用户剧情、科幻、动画、悬疑、动作、爱情、纪录片、恐怖、喜剧用户 > 元数据源
地区与语言元数据源 / 文件名解析华语、欧美、日韩、其他；原声语言用户 > 元数据源 > 自动推导
年份与年代元数据源 / 文件名解析2024、2020 年代、90 年代用户 > 元数据源
时长区间系统按文件时长归集短片（< 40 分钟）、正片（40–150 分钟）、长片（> 150 分钟）系统自动，不可手动编辑
画质与规格系统按文件属性归集4K、1080P、720P、HDR、高码率系统自动
来源系统按媒体源归集媒体源名称、本地 / 网络系统自动
观看状态系统按播放进度归集未看、在看、已看、收藏系统自动，用户可手动改为已看/未看
字幕状态系统检测有内嵌字幕、有外挂字幕、无字幕、已生成实时字幕系统自动
自定义标签用户自由创建「周末重看」「给孩子看」「待整理」用户，可锁定

检索规则（本文件唯一权威定义）

  • 单标签点击：立即筛选出包含该标签的影片，筛选条上出现对应标签，再点一次取消。
  • 组合逻辑：同一维度内多选为「或」，跨维度之间为「与」。 例：类型选「科幻 + 动画」、地区选「欧美」= (科幻 或 动画) 且 地区为欧美。
  • 排除：标签可被设为排除（如「排除恐怖」），排除作用于最终结果（P1）。
  • 搜索框：对标题、简介、标签名、演员/导演（来自元数据源）做匹配；与标签筛选为「与」关系。搜索词为空时不影响筛选结果。
  • 结果为空：显示空状态，列出当前生效的标签，并提供「移除某个标签」与「清空筛选」的直接入口。
  • 标签来源冲突：元数据源刷新的标签不得覆盖用户手动添加或已锁定标签；自动推导标签在用户显式反对后不再出现（进入该条目的「标签黑名单」）。
  • 标签合并：同义标签（如「科幻」与「Sci-Fi」）按统一名称合并展示，保留原始写法作为别名，避免同一维度出现重复项。
  • 保存筛选：当前筛选组合可保存为「智能集合」并出现在导航区，内容随库更新自动变化（P1）。

结果与状态变化

筛选即时生效于海报墙，不产生持久数据（除 P1 的智能集合）。用户新增/删除自定义标签会立即影响该条目的标签与其他筛选结果。

异常与边界

场景系统行为
标签数量过多（如自定义标签上百）按使用频次排序，超出部分折叠为「更多标签」入口
筛选组合无结果空状态 + 已生效标签清单，不自动放宽条件
元数据源不可用导致新条目无标签条目仍可被搜索与播放，仅缺少自动标签；标记「标签待补全」

07播放器与续播 FR-04

目的：提供完整观看能力，并作为实时字幕与多屏播放的承载界面。

播放控制

  • 播放 / 暂停、进度拖拽（含时间预览）、音量、静音、倍速（0.5x–3.0x）、全屏、画面比例、截图。
  • 音轨选择：列出文件内的全部音轨，默认选优先语言音轨；选择后本轮播放内锁定。
  • 字幕轨道选择：见第 4 节「字幕轨道优先级」；同时提供字幕样式设置：字号、颜色、描边、位置（上/中/下）、时间轴偏移（±10 秒，步长 0.5 秒）。
  • 键盘与遥控：空格播放/暂停、方向键快进快退、F 全屏、C 切换字幕、S 开启实时字幕。方向键焦点导航用于后续电视大屏形态，P1。
  • 在线地址播放时，允许边下边播并显示缓冲状态；缓冲期间显示已缓冲时长。

进度记忆与续播

  • 播放超过 30 秒且进度超过总时长 2% 时开始记录；退出播放、关闭应用、切换影片均会写入。
  • 再次打开该条目时，若存在有效进度则显示「继续观看 62%」与「从头播放」两个选项；用户超过 [TBD] 秒未选择则默认继续。
  • 进度达到总时长 95% 视为「已看」，标记为已看状态，不再提示续播。
  • 用户手动拖到片尾或选择「从头播放」会覆盖既有进度。
  • 海报悬停预览不算观看：预览只读取画面与音频，不写入观看进度、不改变「在看 / 已看」状态，也不进入续播提示（见第 11 节「预览实例与进度隔离」）。

异常与边界

编码/封装不被当前解码能力支持提示「当前设备无法直接解码」，提供切换解码方式的重试入口；仍失败则给出「转换为兼容格式」入口（P1）

使用场景 [假设, TBD] 本文档按「一屏多路观看」定义该能力：用户在同一窗口内同时播放 2 路以上视频，可指定哪一路出声（对比观看、家庭分屏、多路录像同时查看）。 若实际场景是「同一部影片多设备同步播放」或「画中画小窗」，功能定义会不同，见开放问题 Q4。

每格能力与规则

  • 每格独立拥有：影片、播放进度、播放/暂停、音轨、字幕轨道、倍速。操作某格不会影响其他格。
  • 音频焦点（单声道输出）：同一时刻只有一路处于「发声」状态，其他路静音播放。点击某格右上角可切换发声窗口。切换为即时生效，无过渡停顿。
  • 混合输出（P1）：允许多路同时出声并各自独立调节音量；由于混音会显著影响体验，默认关闭，由用户在设置中主动开启。
  • 主窗口：双击某格放大为主窗口，其余缩为侧边条；再次双击还原布局。
  • 交换：拖拽一格到另一格可交换两格的影片与进度（P1 拖拽交互）。
  • 实时字幕：默认仅在发声窗口可用（见 FR-05 多屏联动）。
  • 路数上限：由设备能力决定，默认上限 4，用户可在设置中调整；达到上限时新增请求被拒绝并提示当前上限与调整入口。
  • 悬停预览：多屏播放期间不提供海报悬停预览——预览与多屏共享同一份解码额度，多屏播放时浏览海报墙只显示信息层并在浮层标注原因（见第 11 节「预览实例与进度隔离」）。
  • 退出：退出多屏时，询问「保留播放进度并回到单路」或「全部停止」；选择保留时，音频焦点窗口的进度被记忆。

10可迭代性要求 FR-07

目的：落实需求 5「架构上能够支持持续迭代」。本节只描述产品层面的可扩展约束与用户可见的兼容承诺，不指定技术实现（技术架构另出方案）。

可扩展点产品层要求约束的原因
媒体源类型新增一种源类型时，既有的入库、标签、检索、播放行为保持不变在线源类型很可能持续增加（网盘、订阅、局域网设备）
元数据与海报来源数据来源可切换、可新增、可关闭；某一来源失败时其余来源仍可完成抓取，且不影响已锁定的用户数据单一来源失效不应导致整库不可用
字幕能力识别与翻译能力可替换、可增删语种；所有生成结果统一为「字幕轨道」对象，播放器行为与来源无关实时字幕是本产品最可能迭代的部分
标签维度新增筛选维度不需要改变检索交互，维度以配置方式接入标签体系会随使用不断生长
界面模块海报墙、播放器、字幕、多屏为可独立升级的模块，任一模块升级不要求整库重新入库避免小改动引发全量重建
数据可迁移用户数据（标签、收藏、观看进度、生成的字幕轨道、设置的隐私选项）可导出与导入；升级后用户数据不丢失不迁移数据会阻塞任何一次升级
功能开关新功能默认关闭、可逐步放开，出现问题时用户可关闭该功能而继续使用其余部分保证单个新功能失败不拖垮主流程
对用户可见的兼容承诺
  • 升级到新版本后，用户已添加的媒体源、已编辑的标题与海报、自定义标签、观看进度、保存的字幕轨道全部保持有效，无需重新入库。
  • 新增的模块可以独立关闭，关闭后原有播放与检索流程不受影响。

11共享规则与异常

字幕轨道优先级

本规则为全文唯一权威定义，FR-04 与 FR-05 均引用此规则：

用户手动指定（已锁定）> 外挂字幕文件> 内嵌字幕轨道> 实时生成
  • 用户手动选择某条轨道后，该影片置为「字幕已锁定」，后续新增的字幕文件或刷新结果不会改变默认选择。
  • 同一优先级的多个轨道按语种偏好与用户最近选择排序。
  • 实时字幕属于最低优先级，因此只要出现可用的外挂或内嵌字幕，实时字幕入口的推荐位置后移，但用户仍可主动叠加。

标签来源与冲突

  • 来源优先级：用户手动 > 元数据源 > 自动推导。
  • 用户锁定某标签后，该标签不再被任何自动流程移除。
  • 用户明确反对某个自动标签后，该标签进入该条目的黑名单，不再自动出现，但在筛选维度中仍可被用户主动添加。

音频焦点（多屏）

  • 单声道输出模式：仅一路发声；切换发声窗口即时生效。
  • 发声窗口默认是进入多屏时的第一路；用户切换后保持，直到窗口关闭或用户再次切换。
  • 发声窗口被关闭时，音频焦点自动移交给当前仍在播放的窗口（按屏位顺序）。
  • 实时字幕仅跟随发声窗口可用（可放宽）。

预览实例与进度隔离（悬停自动播放）

本节为全文唯一权威定义，FR-02 / FR-04 / FR-06 均引用此规则：

规则定义
实例性质悬停预览是一路独立的低优先级播放实例，与正式播放实例互不复用、互不干扰。
音频预览强制静音，不参与音频焦点决策，因此既不打断单路播放，也不抢走多屏的发声窗口。
并发同一时刻只允许 1 路预览；移入另一张海报时先终止上一路，再从头播放新的片段。
进度隔离预览不写入观看进度、不改变「在看 / 已看 / 收藏」状态、不产生续播记录；移开或未播完即丢弃，不复用位置。
额度共享预览与多屏播放共享同一份并发上限；额度不足时预览被拒绝，不抢占已在播放的窗口，并在浮层标注原因（可见的降级）。
资源优先级出现解码紧张时，预览最先被终止，其次才考虑降低多屏画质；用户已开启的播放窗口不被自动关闭。
可关闭设置中可整体关闭悬停自动预览；关闭后悬停只显示信息层，不改变其余浏览行为。

12开放问题

以下问题会实质改变范围、成本或核心流程，需要评审时给出结论；其余缺口已在上文以 [假设] 标记。

Q1 · 首发平台与形态

影响全部界面与交互。默认判断：桌面客户端、Windows 优先，电视大屏与投屏后置。需确认。

Q2 · 在线资源的边界与合规

P0 目前只覆盖「可访问的视频直链」。是否要支持网盘、订阅型在线源或第三方平台内容，会显著改变功能范围，并引入合规与授权边界问题（是否仅处理用户自有或获得授权的资源）。需确认。

Q3 · 实时字幕的识别与翻译放在本地还是云端

决定成本（云端按量计费）、隐私承诺（音频是否离开本机）、离线可用性与最低硬件要求，并决定「目标延迟」这个数值能否给出。需确认。

Q4 · 多视频同时播放的真实场景

当前按「一屏多路、单一发声」定义。若真实诉求是画中画、多设备同步播放或监控墙式长时运行，交互与资源策略都要重写。需确认。

Q5 · 原始需求第 3 条「并且移动到」的含义 — 已确认

v1.1 已由用户确认为「鼠标移动到海报上自动播放该影片的精华片段」，悬停主行为是静音自动预览，并已升级为 P0（见 FR-02）。本条不再作为开放问题；只剩「哪 30 秒算精华」的判定基线待定，见 Q7。

Q6 · 是否需要多用户与多设备共享同一片库
